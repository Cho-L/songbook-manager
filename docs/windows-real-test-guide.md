# Windows 실사용 테스트 안내서 (Phase 3.7)

샌드박스에서는 외부 서비스(LRCLIB·MusicBrainz)·실제 YouTube·OBS 에 연결할 수 없어서 아래 항목은 **직접 확인이 필요**합니다.
(자동 테스트 = 모의 서버. 아래 절차 = 실제 환경. 둘을 섞어 보고하지 않습니다.)

## 0. 준비 (한 번만)
- Node.js 20 이상 설치 → PowerShell 에서 `node -v` 로 확인
- 프로젝트 폴더에서: `npm ci`
- (선택) MusicBrainz 식별용 연락처: `$env:MB_CONTACT="you@example.com"` (User-Agent 에만 들어가며 결과 파일에는 안 나옵니다)
- 필요한 환경변수는 없습니다. API 키/Supabase 비밀키/토큰은 이 테스트에서 쓰지 않으며 출력되지도 않습니다.

## 1. 실제 API 검증 (LRCLIB + MusicBrainz) — 예상 1~3분
```powershell
npm run check:real-api
# 한 입력만: npm run check:real-api -- --only=3
# 가사 앞 3줄 한글 발음까지: npm run check:real-api -- --pron
```
- MusicBrainz 규칙 준수: 요청 간격 1.1초, User-Agent 지정. 연속으로 자주 돌리지 마세요(차단될 수 있음).
- 화면에 6개 입력별로 ①실제 요청 주소 ②HTTP 상태 ③아티스트 식별 ④후보 ⑤아티스트별 곡 목록 ⑥곡 선택 후 가사 ⑦싱크 여부가 PASS/FAIL/BLOCKED/NA 로 나옵니다.
- **가사 없음 vs API 오류**: 응답은 200 인데 가사가 없으면 FAIL("가사 없음"), 연결 실패/4xx/5xx 면 BLOCKED("서비스 오류")로 구분됩니다.
- 정상 결과 예시(기대):
  - 4번 `踊り子 / Vaundy`, 6번 `君はロックを聴かない / あいみょん`: 후보 "제목 일치 · 자동 선택됨", 싱크 가사 PASS (LRCLIB 에 그 곡이 있을 때)
  - 3번 `Odoriko / Vaundy`: MusicBrainz 별칭으로 踊り子 를 찾아 "별칭으로 제목 일치"
  - 1·2·5번(한글 제목): **자동 선택되지 않고** "후보로 표시(직접 선택)" — 이것이 정상입니다. 한글 제목을 번역해 자동 연결하지 않습니다.
- 결과 파일 `real-api-report.md` / `real-api-report.json` 이 현재 폴더에 생깁니다. 요청 주소·상태·곡 정보만 들어 있어 **그대로 공유해도 됩니다**(개인정보·키 없음). 확인 후 파일 내용을 붙여 주세요.
- 실패 시: 화면 로그의 `NETWORK_ERROR (ENOTFOUND/ECONNRESET…)` 는 인터넷/방화벽/프록시 문제, `429` 는 요청 과다(몇 분 뒤 재시도), `5xx` 는 서비스 쪽 문제입니다.
- 스크립트 자체 점검(가짜 응답, 실제 검증 아님): `npm run check:real-api:selftest`

## 2. 앱 실행 후 화면 확인 (실제 YouTube 포함) — 예상 15~20분
```powershell
npm run dev
```
브라우저에서 표시된 주소(보통 http://localhost:5173)를 엽니다. 곡 하나에 실제 YouTube MR 주소와 싱크 가사(또는 자동 검색)를 준비하세요.

### 2-A. YouTube / 가사 싱크
- [ ] 영상 재생 / 일시정지 / 재개 — 가사 현재 줄이 멈췄다 이어지는가
- [ ] 진행 막대로 탐색(Seek) — 현재 줄이 바로 따라오는가
- [ ] 버퍼링(네트워크 느리게: 개발자도구 Network → Slow 4G) 중 가사가 앞서가지 않는가
- [ ] 다른 곡으로 이동 — 이전 곡 가사가 남지 않는가
- [ ] ±0.5초 싱크 보정 버튼 — 누를 때마다 0.5초씩, 값이 누적되는가
- [ ] "현재 부분이 싱크 시작" — 지금 부르는 줄에서 누르면 그 줄이 지금 시간에 맞춰지는가
- [ ] 앵커를 다시 설정 — 보정값이 중복 누적되지 않고 새 기준으로 바뀌는가
- [ ] 새로고침 후 보정값 복원
- [ ] 일본어 가사에서 원문 + 한글 발음이 같은 줄에 함께 보이는가 (처음엔 사전 약 18MB 다운로드: "사전 내려받는 중" 안내 → 재방문은 즉시)
- [ ] 사전 다운로드 실패 시(네트워크 끊고 시도) 안내 문구 + 재시도 버튼

### 2-B. 다국어 검색 화면 (실제 API)
- [ ] 곡 "무희 / 바운디" 추가 → 자동 선택 안 됨 → "가수별 곡 찾기" → 가수 선택 → 곡 목록에서 踊り子(Odoriko) 선택 → 가사 후보 → 미리보기 → 적용
- [ ] "Odoriko / Vaundy" 곡은 자동으로 踊り子 가사가 잡히는가
- [ ] 밝은 테마(설정에서 변경)에서 자동 가사 영역 글씨가 잘 보이는가 (Phase 3.7 에서 수정)

## 3. OBS 실제 방송 흐름 — 예상 20~30분
OBS 는 샌드박스에서 실행할 수 없었습니다. 이 앱은 "OBS 브라우저 소스가 지금 열려 있는지"를 알 수 없는 구조라서, 화면의 "OBS 대기열 반영" 표시는 **서버가 OBS 에 줄 대기열이 관리자 목록과 같은지**만 뜻합니다. OBS 가 실제로 보이는지는 아래로 직접 확인하세요.
1. 관리자 → 신청곡 대기열에서 접수 켜기, OBS 대기열 주소 복사 → OBS 소스 추가 → 브라우저 → 붙여넣기
2. 시청자 신청 주소를 다른 기기/시크릿 창에서 열어 신청
3. 체크:
- [ ] 신청 → 관리자 "확인 대기"에 나타남 → 승인 → 대기열 표시 → "방송 현황"의 다음 곡이 맞음
- [ ] OBS 대기열 화면이 몇 초 안에 갱신 (승인/순서 변경/완료)
- [ ] 재생 → 현재 곡 ▶ 표시, 가사 오버레이(/overlay/lyrics 주소)에 가사 줄이 노래에 맞춰 바뀜, 한글 발음 함께 표시
- [ ] 다음 곡 이동 → 완료 → 대기열이 비면 "대기 중인 신청곡이 없어요" 표시
- [ ] OBS 소스 우클릭 → 새로고침 → 현재 상태 복구
- [ ] 장면 전환(소스가 비활성→활성) 후 상태 복구
- [ ] PC 인터넷 끊기(Wi-Fi 끄기) 30초 → 복구: 마지막 목록 유지 + 작은 주황 점, 처음부터 연결 안 되면 "대기열 서버에 연결하지 못했어요" 문구 → 복구 후 자동 갱신
- [ ] 장시간(1시간 이상) 켜 둔 뒤에도 갱신이 계속되는가
- [ ] 글자가 방송 해상도에서 잘 읽히는가(밝은/어두운 배경 화면 위)

## 4. 결과 공유 방법
- 1번 결과: `real-api-report.md` 내용
- 2·3번: 체크리스트에서 실패한 항목 + 가능하면 화면 캡처(개인 정보가 보이면 가려 주세요)
- 앱에 문제가 있을 때 개발자도구(F12) Console 의 빨간 오류 문구(주소에 토큰/키가 있으면 지우고)
