# Phase 3.3 — 일본어 발음 · 자동 발음 · 싱크 앵커 · 검색 근거

## 1. 일본어 발음 엔진
- 파이프라인: 원문 → 형태소 분석(@patdx/kuromoji, IPAdic) → 단어별 읽기 → 조사(は→わ, へ→え, を→お: 품사가 조사일 때만) / 숫자+단위(2人→ふたり) 처리 → 가나 정규화 → 한글(`kanaToHangul`) → 검증.
- 표기 정책(일관): か행 카키쿠케코, が행 가기구게고, 촉음 っ→ㅅ 받침, ん→ㄴ 받침, 장음은 늘어나는 소리를 적는다 (お단+う→오: 希望→키보오, う단+う→우: 空気→쿠우키, ー→앞 모음 반복: ラーメン→라아멘).
- 띄어쓰기: 자립어 + 뒤따르는 조사/조동사/접미를 한 덩어리로 묶는다 (少し 寂しそうな 君に → 스코시 사비시소오나 키미니).
- 검증: 결과에 가나/한자가 남으면 `unsupported`("검토 필요") + 실패 단어 목록(`failed`). 읽기가 문맥에 따라 갈릴 수 있는 한자(人·日·今日 등)는 `review` + 단어 목록(`uncertain`).
- 분석기 없이는 한자를 추정하지 않는다(한자 줄은 검토 필요, 원문 유지).

### 분석기 선택
| 후보 | 결과 |
|---|---|
| kuromoji (원조) | CommonJS/XHR, Node·브라우저 로더 혼재, 2022 이후 정체, 사전 41MB(비압축 포함 패키지) → 제외 |
| **@patdx/kuromoji 1.0.4** | ESM·TypeScript 정의·fetch 기반 로더 교체 가능·Apache-2.0·사전 gz 18MB → **채택** |
| @sglkc/kuromoji | 브라우저 로더 있으나 CommonJS, 정의 없음 |
| @aiktb/kuromoji | 사전이 비압축 100MB 규모 → Cloudflare 파일 크기/배포 부담 |
- 사전: `dict/*.dat.gz` 12개, 합계 약 18MB(gzip). `vite.config.ts` 플러그인이 `node_modules` 에서 dev 미들웨어/빌드 산출물(`dist/kuromoji-dict/`)로 복사한다 — 저장소에 사전을 넣지 않고 CDN에도 의존하지 않는다.
- 로드: 일본어 줄을 처음 변환할 때만 라이브러리 + 사전을 내려받는다(초기 로딩 영향 없음). 진행 중 요청은 하나만 공유하고, 실패하면 캐시를 비워 다시 시도할 수 있다. gzip 은 브라우저 `DecompressionStream` 으로 해제하고, 서버가 이미 풀어 보낸 경우도 처리한다. 20줄마다 이벤트 루프에 양보해 긴 가사에서도 화면이 멈추지 않는다.
- 한계: 같은 한자의 문맥별 읽기(生, 行 등)는 사전의 대표 읽기를 쓴다 → 모호한 한자는 "읽기 확인" 표시. 사전 첫 다운로드 약 18MB(이후 브라우저 캐시, `public/_headers` 7일).

## 2. 가사 후보 → 자동 발음 → 저장
후보 선택 → 원문 미리보기 → (교체 모드, 일본어/영어 줄이 있을 때) 자동 발음 생성 → 줄별 수정 → "이 가사 적용" → 원문+발음 저장. 발음을 만드는 동안 적용 버튼은 잠시 비활성. 변환 실패 줄은 발음 없이 저장(원문 적용은 항상 가능), 불완전(한자 남음) 발음은 저장하지 않는다. "다시 시도"로 사전 재로드. 한국어 줄/영어 정책은 기존과 동일. 자동 찾은(임시) 가사는 발음 패널에서 "가사 + 발음 저장"으로 저장할 수 있다. 시간 정렬("내 가사 유지 + 시간만 입히기")은 기존 발음을 보존하며 새로 만들지 않는다.

## 3. 발음 다시 만들기
저장된 발음은 덮어쓰지 않고 새 값을 "제안"(저장됨 → 새로 만든 값)으로만 보여 준다. 줄별 "새 값 사용" / "새 값 전부 사용(확인)" / 선택 줄만 다시 만들기, 직접 고친 값 보호, 덮어쓰기 확인, 저장 전 백업 + "되돌리기", 한자가 남은 줄은 저장 차단. DB 변경 없음(`{발음}` 보조 줄 그대로).

## 4. 「현재 부분이 싱크 시작」
- 기존에는 이 이름의 기능이 없었고, 자동으로 찾은 가사 전용 "지금이 첫 소절 시작"(첫 줄만 기준)만 있었다. 저장된 싱크 가사용 앵커를 새로 추가했다.
- SongMode "싱크 맞추기" → 지금 부르는 가사 줄(기본값 = 현재 줄)을 눌러 선택 → "현재 부분이 싱크 시작" → 보정값 = 현재 재생 시간 − 선택한 줄의 **원래** 시간 (절대값). 예: 원래 1:10, 지금 1:25 → +15초, 모든 줄이 같은 만큼 이동.
- 다시 맞춰도 겹쳐 더해지지 않는다. ±0.5 미세 조정은 같은 값 위에서 이어진다. 한도 ±120초(초과 시 적용 안 함). 재생 중/일시정지 모두 가능(플레이어의 실제 현재 시간 사용), 배속·seek 와 무관(영상 시간 기준).
- 저장: 3.2 와 동일(브라우저 localStorage, 곡별). ConcertMode/OBS 는 같은 보정값/보정된 시간표를 사용. 자동 찾은 가사는 기존 warp 에 차이만큼 더한다(이중 적용 없음).

## 5. 검색 근거
- 점수(정렬용)와 근거를 분리: `evidence { title, artist, level, label, notes }`. 화면에는 % 대신 "아티스트 일치 · 제목 일부 일치 · 확인 필요" 처럼 근거 표시(퍼센트는 확률이 아님).
- 번역 제목(너는 록을 듣지 않아 ↔ 君はロックを聞かない)은 같은 곡이라 단정하지 않는다. 제목 속 외래어(ロック→록)가 이어지면 약한 근거(제목 점수 상한 0.5, 자동 선택 불가)로만 반영해 같은 가수의 다른 곡과 점수가 갈린다.
- 聞/聴 등 이체자·구자체는 같은 글자로 비교(`KANJI_VARIANTS`). 아티스트 별칭(아이묭/あいみょん/Aimyon)은 기존 별칭 사전·곡 별칭 연결을 그대로 사용. 재생 길이는 점수에 넣지 않고 미리보기 보조 정보로만 쓴다. 추가 외부 요청 없음.
