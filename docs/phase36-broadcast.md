# Phase 3.6 — 방송 실전 사용성 및 통합 안정화

## 조사 결과 (코드 기준)
재사용·유지(문제 없음 → 수정 안 함): 신청 중복/도배 방지, 승인·거절 동시 처리 충돌 방지(조건부 UPDATE), 재생 시작(start_song_request RPC + 폴백), 관리자 5초 폴링, OBS 대기열 4초 폴링·백오프·탭 복귀/online 즉시 재조회, 같은 브라우저 BroadcastChannel 즉시 알림, OBS 가사 오버레이의 heartbeat/stale/재연결 상태(Realtime link), 가사 싱크·발음 동시 표시(같은 lineIndex).

확인된 실제 문제(수정):
1. 관리자 화면에 현재 곡/다음 곡/대기 건수/접수 상태/OBS 반영 상태를 한눈에 보는 곳이 없었다 (재생 중 곡이 대기열 목록 안에 섞여 있음).
2. 서버 연결이 끊겨도 관리자 화면은 "마지막 갱신 시각"을 알려 주지 않았다.
3. OBS 대기열 화면이 처음부터 서버에 연결하지 못하면 "불러오는 중…"만 계속 표시됐다 (실패인지 알 수 없음).

## 변경
- `RequestQueuePage.tsx`: 상단 "방송 현황" 요약(현재 곡·다음 곡·확인 대기·대기열·접수 켜짐/꺼짐·OBS 반영 상태·마지막 갱신 시각·연결 실패 시 안내). 기존 목록/버튼은 그대로.
- `utils/queueOverlay.ts`: `compareQueues` — 관리자 대기열 vs 서버 공개 대기열(OBS 가 읽는 것) 비교. 공개 대기열을 못 읽으면 "확인하지 못했어요"(정상으로 표시하지 않음).
- `QueueOverlayView.tsx`: 연결 실패가 계속되면 "대기열 서버에 연결하지 못했어요 (다시 시도 중)" 표시. 데이터를 받은 뒤 끊기면 기존대로 마지막 목록 유지 + 작은 점.
- 한계 명시: OBS 브라우저 소스가 실제로 열려 있는지는 알 수 없다 → "서버가 OBS 에 줄 대기열과 같은지"만 표시하고 화면에 그렇게 안내한다.

## 변경하지 않은 것
DB/스키마, Auth/RLS, Repository, Import/Export, Playlist 이동, YouTube 재생, OBS URL 형식(모두 그대로), server_error 처리.
