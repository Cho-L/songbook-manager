# LYRICS-01: 버전·녹음 후보·자동 캐시 안전화

기준 main: `6a9125d`. [PR #8](https://github.com/Cho-L/songbook-manager/pull/8)의 `7de3199`와 해당 커밋의 `docs/issue-7-phase-one-audit.md`를 읽었다. PR #8은 아직 Draft여서 감사 파일은 main에 없다. 무관한 채팅 모델/감사 전체를 가져오지 않고 LYR-VERSION, LYR-REVERSE, LYR-DEDUPE, LYR-CACHE 사례를 새 안전 기대 테스트로 작성했다. 이 문서는 PR #8 병합이나 운영 검증을 뜻하지 않는다.

## 변경 동작

- `versions.ts`는 실제 입력 제목과 후보 제목을 **양방향** 비교한다. Live/라이브/ライブ, Cover/커버/カバー, MR/Instrumental/Off Vocal/伴奏 등, acoustic, remix, edit, remaster, 일반 version 표기를 구분한다. Live at Tokyo/Osaka처럼 추가 녹음 설명도 같지 않으면 자동 선택하지 않는다. 알려진 동의 버전 표기는 같은 분류로 취급하고, 원곡과 호환되지 않는 표기·모호한 version은 보수적으로 사용자 선택으로 보낸다.
- 버전 차이는 점수 -0.15 감점에 더해 `isAutoAccept`의 **차단 조건**이다. 다국어 제목 별칭도 실제 요청 버전과 후보 버전의 차이를 덮어쓰지 못한다. 다른 버전 후보에 high 근거 표시를 하지 않는다. 제목/가수 근거가 낮으면 기존처럼 사용하지 않는다.
- 후보 dedupe는 같은 provider/ID와 제목·가수·길이·앨범·가사 데이터가 같은 반복 관측만 합친다. 다른 ID/길이/버전/출처/타이밍은 제목·가수만 같다고 버리지 않는다. ID/출처가 없으면 중복임을 추정하지 않는다.
- 자동 선택 기준을 만족하는 서로 다른 녹음 후보가 제목·가수 각각 0.05 이내의 유사도 근거를 가지면 `needs-choice`다. 싱크 가사가 있다는 사실만으로 다른 녹음의 평문 가사 후보보다 먼저 고르지 않는다. 이 수치는 기존 점수의 확률이 아니라 보수적인 근거 비교 기준이다. 반환 후보 목록은 기존처럼 최대 8개다.
- 명시적 `candidateId` 선택은 유지한다. 사용자가 미리보기 후보를 고르면 pool을 재사용하고 버전 경고를 유지하며, provider가 준 시간만 사용한다. 평문 가사에 임의 timestamp를 만들지 않는다.
- 캐시 titleKey는 괄호 속 버전 설명을 보존한 전체 제목 정규화와 `lyrics-match-v2:` 정책 태그를 사용한다. `SyncEntry.v=1`/저장 구조는 유지하지만 이전 정책 캐시는 재사용하지 않는다. 제목 변경 직후 effect 전 렌더에서도 무효한 entry를 가사에 적용하지 않는다.

## 호환성과 제한

기존 저장 가사/곡/노래책/DB·API·OBS 메시지 포맷/선택된 MR 영상은 바꾸지 않는다. 기존 다국어 별칭, plain/synced 결과, 영상별 자동 warp의 수식·출력 및 기존 전체 회귀 테스트를 유지한다. 이미 곡에 저장된 LRC는 자동 수정하거나 잘못된 버전이라고 일괄 삭제하지 않는다.

**자동 캐시 정책 전환의 영향:** 앱을 다음에 실행하면 이전 정책의 브라우저 자동 가사 캐시가 무효화되어 기존 설정에 따라 재검색/사용자 재선택이 필요할 수 있다. 이전 자동 캐시 안에만 있던 영상별 warp 보정도 재설정이 필요할 수 있다. 별도의 곡별 수동 offset과 DB 저장 가사/MR 링크는 변경하지 않는다. 이번 작업에서는 사용자 localStorage/DB를 읽거나 바꾸지 않았다.

분류는 제목 metadata 기반의 보수적 휴리스틱이다. 제목에 버전 단어가 원래 포함돼 있으면 수동 선택이 늘 수 있다. 표기 없는 다른 녹음, provider가 누락한 정보, 반환되지 않은 후보, 같은 버전 태그를 쓴 서로 다른 오디오까지 판별하지 못한다. 일반적인 여러 녹음은 별도 후보로 유지하지만 실제 오디오 일치를 검증한 것은 아니다. 검색 API의 기존 요청 상한은 유지되며 버전 gate로 조기 자동 선택이 줄어 기존 상한 안에서 검색 단계가 늘 수 있다. 운영 API는 호출하지 않았다.

PR #8의 LRC-PARSERS 및 CHAT-MATCH는 이번 범위가 아니다. 직접 저장 LRC의 offset/multi-tag 파서 통합이나 채팅 구현을 변경하지 않았다. PR #8의 옛 가사 `KNOWN GAP` assertion을 이후 병합할 때는 이 안전 기대값과 맞춰야 하며 결함 동작을 정상 기대값으로 다시 들여오면 안 된다.

## 검증과 롤백

검증은 가짜 provider/가사만 사용한다. 새 테스트는 네트워크 호출 시 실패하는 guard를 둔다. 현재 main의 전체 단위 테스트에 버전 차이 양방향, KO/EN/JA 버전 동의어·추가 설명, alias 우회 거부, 명시적 선택, 중복/녹음 보존·선택, 다국어 정상 싱크, timestamp 보존, 구 캐시 무효화·새 캐시/warp 호환성을 추가했다.

롤백은 이 변경 커밋의 `git revert`다. DB·Worker·환경변수/시크릿·의존성 변경은 없다. 사용자 지시에 따라 로컬 커밋까지만 수행하며 GitHub 푸시/PR 생성·Cloudflare 미리보기·운영 배포는 수행하지 않는다.
